name: submit-check
description: 제출 전 최종 점검과 서술형 대비. 필수 파일·실행·문서를 확인하고, Ally가 AI 없이 답할 수 있도록 외울 수 있는 설명 카드를 만든다. "제출 점검", "submit"에 사용.
---

1. 과제 안내의 제출 형식·필수 파일과 실제 파일을 대조 (경로·파일명 정확히). 형식은 과제 안내가 유일한 기준.
2. 처음부터 실행 재현. 실패는 고칠 수 있는 것만 고치고 나머지는 한계로 문서에 명시.
3. 제출 문서에 판단과 근거 / 검증 결과 / 남은 한계가 있는지 확인. 비밀값·임시 파일 제거.
4. **설명 카드** — 제출 후엔 파일을 볼 수 없으니 외울 수 있게 10줄 이내, Ally 1인칭 문장으로:
   - 문제: 누구의 어떤 문제를, 왜 이렇게 정의했나
   - 핵심 결정 3개: 무엇을 / 왜 / 버린 대안 (DECISIONS의 💬 활용)
   - AI 제안 중 안 쓴 것과 이유 1~2개
   - 방향 전환 1개: 무엇을 시도했고 왜 바꿨나
   - 검증: 어떻게 확인했나 / 한계와 다음에 할 일
   - 요구사항과 구현이 다른 부분과 이유
5. Ally가 원하면 3분 리허설: 예상 질문 3개를 하나씩 → Ally가 짧게 답 → 빠진 근거만 한 줄 피드백.
6. 👉 Ally: 탭 옆 "저장됨" 확인 → "제출하고 문제풀기".
